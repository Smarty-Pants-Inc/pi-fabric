# Linux execution cgroup custody

A dedicated systemd user scope owns execution membership on cgroup v2. The worker transfers the execution scope and identity to the parent before opening the target's admission pipe. An inherited service cgroup is never whole-tree signal authority.

Custody opens the scope directory once with `O_RDONLY | O_DIRECTORY`, compares `fstat` with its recorded device/inode, and performs procs/events/kill operations through `/proc/self/fd/<fd>/<file>`. Replacing the pathname cannot redirect signal authority. The fd closes after empty/removed scope confirmation; an active kill write retains it until completion.

Admission requires writable `cgroup.kill`. If it is missing or unavailable, callers use the existing legacy process-group custody with a downgrade warning, not a weakened cgroup receipt. KILL uses pinned `cgroup.kill` only. Losing the control after admission fails closed; there is no numeric KILL fallback.

**ponytail — cooperative TERM is skipped on the cgroup path.** Node and Bun have no pidfd signal API. Freezing does not stop another same-UID process from moving a member through a sibling `cgroup.procs`; the moved process can exit and its PID can be reused after the last exact-path/start-time check. A recorded process group can likewise retain migrated out-of-scope members, so it is not scope-only authority. The receipt sends neither per-PID nor process-group signals (including TERM). Callers still allow the existing grace period, then write `cgroup.kill`, which atomically targets only current members, including setsid children and orphans. The trade-off is loss of cooperative OS TERM handling for execution targets. Fabric workers can still record stop intent through the existing captured native IPC `fabric-stop` message; this is best-effort, not a numeric signal, and a failed/disconnected channel does not erase the grace/KILL obligation. Stop during scope handoff cancels the pending ACK deadline without opening the target gate. Native-close and tree-exit fences remain required. `cgroup.freeze` is no longer needed for admission because it cannot make numeric signalling safe.

Only scoped targets lose `DBUS_SESSION_BUS_ADDRESS` and `XDG_RUNTIME_DIR`, through the admission shell's `unset`. Direct-spawn fallback preserves the original environment/options. Removing only the first variable is insufficient: systemd discovers the user bus through the second. Nested Fabric launchers can discover the standard `/run/user/<uid>/bus` for their launcher alone; execution targets are scrubbed again. This is convenience hardening, not a same-UID security boundary.

Observe/exited/isAlive and stop do not enumerate `/proc` on the cgroup path. Exit is latched from the shared `cgroup.events` watcher's `populated 0` notification (recursive membership), not by sampling direct `cgroup.procs` on liveness calls. Drain waiters share that watcher and each has one deadline, with no repeating membership poll or 60-second safety timer. At most one safety read of the pinned `cgroup.events` occurs at the deadline to confirm a missed empty/removal event. Failed watcher creation, watcher loss, or unreadable events retain custody until the deadline; unknown exit is false and triggers the caller's atomic KILL escalation, never a one-second polling fallback. An empty direct `cgroup.procs` does not prove descendant cgroups are empty.

Worker and execution admission markers use a shared directory `fs.watch` subscribed before the first read. Atomic marker rename, native close, cancellation (worker admission), or one five-second deadline settle admission; there is no 10ms marker poll. Watcher failure is non-admission. A failed launcher must confirm native close before direct fallback, and process-transport workers that admit during teardown are never replayed. Execution targets still wait on their owned gate pipe until custody handoff; a failed admission cannot release that gate.

## Accepted security residual (smarty-dev#7478)

Same-UID code can reconstruct user-bus discovery, ask its user manager to re-home a process, or write delegated cgroup membership. A process that leaves the retained scope can evade custody. Scope custody is not a sandbox; strong containment needs a separate UID and/or an enforced policy denying cgroup writes and user-manager access.

There is no stop-time escaper discovery. Matching SID, PGID, or a sampled PPID chain is not ownership of a sibling cgroup; killing an unrelated process is worse than missing an escaper. The live escape test documents this residual and asserts that stopping the original scope does **not** signal a same-session process outside it. Explicit custody of that fixture's separate scope is used only for test cleanup.
