# Linux execution cgroup custody (replacement part 1)

Each Linux worker and each provider execution/resume gets a distinct named systemd user scope when cgroup v2 user-manager custody is available. `agents.processSlice` still selects the worker slice; the Linux default is `app.slice`. Execution scopes use `app.slice`. Other platforms and hosts without cgroup/user-manager capability retain the existing legacy process-group/native-child cleanup. Direct fallback preserves original options/environment; on cgroup-v1 hosts an explicitly configured worker `processSlice` still uses its legacy systemd scope placement.

The launch plan fixes the exact directory from the user manager's root `ControlGroup`, the requested slice hierarchy and a fresh `fabric-worker-<uuid>.scope` or `fabric-execution-<uuid>.scope` unit **before spawn**. A marker cannot supply custody authority: it contains only readiness text, never a cgroup path. Once the captured launcher's birth is in that exact planned scope, custody opens it with `O_RDONLY | O_DIRECTORY | O_NOFOLLOW`, checks current-UID ownership and matching device/inode, requires writable `cgroup.kill`, then verifies exact launcher path, membership and birth. Only then can the admission marker be trusted. Failed ownership/pinning does not release the target or replay execution.

The trusted shell waits on an owned pipe before `exec`. The worker transfers the scope directory **from its spawn result** plus the pinned device/inode/UID over the existing private native IPC channel. The parent pins that exact identity and verifies the still-gated launcher before acknowledging it. A migration between marker write and pin cannot substitute a sibling scope, including one with the same unit basename. Admission cleanup closes the gate (EOF); a held scope that does not drain within the bounded grace escalates through its pinned `cgroup.kill`, never a numeric launcher-kill fallback. A missing native close exposes the existing manager cleanup debt and vetoes replay. Even before the first exact-membership observation, marker existence can only veto replay, never grant custody or supply a path. A late migration check before release also fails closed.

All later cgroup membership/events/kill IO uses `/proc/self/fd/<fd>/...`, not the pathname. Recursive `cgroup.events populated 0`, not an empty direct `cgroup.procs`, confirms scope exit. A replaced pathname cannot redirect the retained pin. Lost controls retain cleanup debt; no numeric fallback is permitted.

**ponytail — cooperative TERM is skipped for cgroup-held work.** Node/Bun expose no pidfd signal API. Same-UID code can move even a frozen member out of the scope, exit and reuse its PID after any `/proc` check; its old PGID may still contain migrated out-of-scope work. Neither PID nor PGID is scope-only authority. Cleanup sends no numeric signals, including TERM or launcher `ChildProcess.kill`. The existing captured `fabric-stop` IPC message requests cooperative worker stop; callers retain today's grace period, then write pinned `cgroup.kill`, which atomically targets only current recursive members, including setsid children and unsampled orphans. Trade-off: execution targets do not receive cooperative OS TERM and their TERM handlers do not run.

This replacement does **not** change manager liveness intervals, membership/admission polling cadence or introduce shared event-driven liveness. Those optimizations belong to replacement part 2. Non-cgroup legacy cleanup is unchanged. No state-backend configuration is changed.

## Accepted security residual (smarty-dev#7478)

[Scope decision](https://github.com/Smarty-Pants-Inc/smarty-dev/issues/7478#issuecomment-6078662369): same-UID code can reconstruct user-bus discovery, request user-manager re-homing, or write delegated cgroup membership. A process that leaves the retained scope can evade custody. Scrubbing `DBUS_SESSION_BUS_ADDRESS` and `XDG_RUNTIME_DIR` from scoped targets is convenience hardening, **not a sandbox**. Strong containment requires a separate UID and/or enforced denial of cgroup writes and user-manager access.

There is no stop-time escaper discovery. SID, PGID and sampled PPID chains are not custody of sibling scopes; an escaped sibling must not be signalled. Tests own any separate fixture scopes explicitly for cleanup.

Owner gate: **fabric-v2** must install a canary on **Ryzen 3** before fleet rollout, and revert on **any orphan or escaped process**. This source task does not perform installation.
