## Stop and preserve first

1. Withdraw affected native ask/cancel routes; stop new affected ingress and broker replay consumption. For uncertain shared-ledger history or a receipt fault, hold the **WHOLE link, ordinary/non-native traffic included**, not merely native deliveries. Earlier admitted work may still settle: a link fault does not undo a business commit.
2. Stop automatic candidate-link restart; stop the link under its normal custody. Quiesce Main and **separately** resident/callback ownership. Consume the actual result, then verify actual native terminal state or a confirmed owned stop. Launcher exit/EOF, BUSY, elapsed timeout and heartbeat lapse do not prove Main or resident termination. Do not start a successor or change resident artifacts while old-generation callbacks may live.
3. Preserve a **SEALED original** before any old/candidate reader open (load may cut a tail/compact). Record hashes, sizes, modes/uid, full candidate/old artifact paths+digests and Git pins, ledger/cursor/config, receipt namespace, pending claims/outcomes, broker/file replay positions, app dedupe state and error/byte-offset evidence. Preserve raw traces and failed working copies. Work only on independently hashed copies under one writer; do not edit/drop a bad line, overwrite a receipt, delete a claim, auto-fresh, auto-restore or replay unknown work.
4. Name the owner and affected scope in the existing incident/issue record. If custody or scope cannot be proved, remain stopped/unavailable; no synthetic ACK, `notRun`, callback completion or exact-identity claim.

|---|---|

**At-most-one-torn-tail guarantee, not power atomicity:** one writer holds normal ledger custody; each fully encoded line uses one append syscall, full byte-count check and successful fsync before visibility or the next append; failures fail-stop, with best-effort cutback. Assume an honest filesystem retaining the previously fsynced prefix, no middle corruption/reordering/lying fsync, and atomic namespace replacement semantics for compaction. Under those assumptions only the last in-progress record can tear, and ca4's existing one-tail cut preserves the durable prefix. Arbitrary filesystem/power corruption is outside this guarantee and follows STOP/seal, never automatic recovery. No new truncation mechanism is required by Q-R4-1(a).

**Upgrade precondition:** keep receipt recipe and complete **issued link scope** (canonical principal/grants/digest and resulting `processSender()` stamp) stable throughout **every retained claim/receipt horizon**: normally `max(deadlineAt, claimedAt) + 24h`, not 24h from deployment or a short session TTL. Otherwise fully drain that horizon under existing custody before changing them. Old ca4 ignores and does not prune `native-ingress/`; rollback does not grant retention cleanup. Reprojection is idempotent **only under those stable inputs**. Absence of new callbacks is not proof that queued broker work or delayed redelivery has drained.

## Lead's backup-or-fresh choice and reconciliation window

The lead records exactly one choice: remain stopped; a named trusted, hashed backup; or separately authorized fresh-ledger recovery. Backup drops post-backup transport dedupe/outcomes; fresh drops all retained transport dedupe/outcomes. **DEDUPE RISK includes delayed/redelivered ordinary commands and effects without an app opKey.** Retaining an old reader/backup is a recovery option, not proof of safe restoration. Never revert S1 alone or run the feature dependency alone; see [handoff](handoff.md#r4-accepted-delta--prep-only-current-status).

Required inputs, extracted/validated by code from owner-provided artifacts (models must not retype principal deliverable values):

- exact recovery owner/authorization and full old/candidate/app artifacts; actual **NEW full reviewed #344 SHA** and schema/migration pin;
- SEALED ledger/cursor/config/receipt hashes and trusted backup identity/cutoff, or explicit fresh-start choice;
- **window start**: last proven complete dedupe coverage at the chosen backup cutoff; for fresh start, earliest affected retained/replayable operation whose transport dedupe is lost. A proposed fresh creation time alone is not a safe start if older broker work can redeliver. If no earliest safe bound is proven, treat the full affected retained/replay history as in scope and stay stopped;
- **window end**: owner-recorded UTC `now` after ingress/replay is held and earlier in-flight work has settled or has been classified unknown; extend through the final pre-resume readback, not just the first query time;
- code-extracted attempt inventory from broker/file/control evidence: seat/operation/opKey, current and prior request IDs/command IDs, canonical semantic args hash, possible entry/commit/outcome timestamps and retained stable result/item identity where evidenced. Missing opKey/seat or unknown application mapping is unresolved, not proof of zero effects;
- actual application dedupe/effect store(s), namespace/uniqueness/transaction semantics, external effect/outbox coverage and authorized read-only access scope. The synthetic SQLite fixture is **not** this production schema/store.

### Pass/fail and traffic resumption

**PASS for a named application scope only** requires complete validated input/window coverage; one stable, authorized matching business effect/result per completed dedupe identity; same identity/different args is refused without another effect; no duplicate effect, unauthorized cached result, unresolved possible commit, missing mapping or unexplained mismatch; all chosen replay positions/cursor/state match the reconciled scope. A no-effect case must be positively evidenced, never inferred merely from an absent transport ACK or receipt. Preserve outputs and current request correlation without exposing other seats.

**FAIL/UNKNOWN** on missing new app pin/query/schema/readback, incomplete window, unknown custody, uncovered external effects, duplicate/conflicting result or unresolved attempt. Keep affected traffic stopped and return the precise gap to fabric-store/inbox342. The owner may authorize a separately reconciled scope, not declare the entire link safe from one application's opKey check.

**Ordinary/non-native residual:** no universal application-opKey guarantee exists for generic bridge traffic. Inventory each affected ordinary operation and its own effect/dedupe authority. If it cannot be demonstrated unaffected or separately reconciled, it **cannot resume**, even if old ca4 opens successfully and app add/list/resolve checks pass. No automatic replay of ambiguous work.

Resume only after the lead's explicit backup/fresh/risk decision, custody barrier, actual installed-reader copied-ledger gate, successful schema-pinned readbacks and reconciled replay/dedupe scope. Recheck the window through resume time. Native routes additionally require exact current native candidate/canary/client/env/seat/data/retention gates; old actor code never opens the native-bearing session. Recovery does not waive them.
