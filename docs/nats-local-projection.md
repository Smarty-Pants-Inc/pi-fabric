# NATS host-local presence projection

With `mesh.transport: "nats"`, each local `ParticipantDirectory` projects only its authenticated transport machine's current participant and host-lease KV rows into the ordinary local files. The projection is one-way: NATS KV remains authoritative; these files are a local compatibility/read model, not a second source of truth. `mesh.transport: "file"` does not create the projection.

## Snapshot, updates, and recovery

The projection watches only `<machine>.p.>` in `presence` and `<machine>.h.>` in `leases`. It never copies another machine's KV rows. It writes participants through `writeParticipantFileIf` and leases through `writeHostLease`, preserving the established local file formats and the readers that already consume them. Projected records carry private `natsProjection` provenance (machine, KV key, owner, incarnation, and KV revision) so a delayed writer or removal cannot replace or delete a newer owner/version. Unchanged participant bytes do not rewrite a file. Lease refresh is coalesced until the local file's expiry is within half of the 15-second host-lease TTL.

NATS KV watchers deliver a current snapshot followed by live changes; the NATS documentation describes the initial snapshot and the null/end marker that separates it from subsequent updates ([Key/Value Store](https://docs.nats.io/nats-concepts/jetstream/key-value-store), [JetStream KV developer guide](https://docs.nats.io/using-nats/developer/develop_jetstream/kv), [watching keys](https://docs.nats.io/nats-concepts/jetstream/key-value-store/watch)). The transport adapter exposes the snapshot boundary as `ready` and recovery as `reset`. A reset causes a fresh snapshot; after each snapshot, local projection entries not observed are checked with a KV `get` before cleanup. A read error is not treated as absence. KV tombstones remove only a local file whose projection marker still identifies the removed key and older owner/revision. Startup, watch recovery and tombstones therefore converge without treating a local file as authority.

A reader that observes both the live NATS view and its local projection must use the current KV row as the authority; it does not let a local timestamp outrank KV. Both copies originate from that same row, so their participant payload, owner incarnation, and source `updatedAt` agree. Readers that merge a local file with its keyed shared-state copy keep the existing rule unchanged: the later `updatedAt` wins and the file wins a tie; a bridge/mirrored state row never outranks a native file. No reader or FILE-transport behavior is changed.

## Operations and rates

`ParticipantDirectory.natsProjectionMetrics` is available only for NATS mode. It identifies the credential-bound `machine` and reports cumulative participant/host-lease file writes (including removals), local reconciliation reads (snapshot/removal scans, write decisions and lease-cache stat checks), KV reconciliation `get` calls, elapsed time, and each count normalized to a per-minute rate. An operator can sample these values once per host to separate steady lease renewal from churn or a recovery resnapshot.

The deterministic one-host rate tests use an injected monotonic fixture clock and exercise a 60-second steady sequence: participant writes 2/min, host-lease writes 7/min, participant-file reconciliation reads 5/min, host-lease reconciliation reads 14/min (the snapshot scan, initial write, six cheap stat validations, and six locked renewals), and KV reconciliation reads 0/min. The test includes lease renewals every five seconds; the file refreshes at ten-second intervals. A separate 60-second one-host churn window with three additions and one removal reports 5 participant mutations/min, 5 host-lease mutations/min, 6 participant reconciliation reads/min, 7 host-lease reconciliation reads/min, and 0 KV reconciliation reads/min. These are deterministic fixture rates, not a claim of measurements on a live NATS host; the metrics expose the corresponding live per-host measurements.
