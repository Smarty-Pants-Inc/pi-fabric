# Root registration ownership

On a native Pi root with `mesh.enabled: true`, Fabric reserves the root before it opens
its followUp journal, root inbox, actor registry, control plane, or participant publisher.
The admission check refuses another live process/session owner with any of:

- the same explicit persisted Pi name, even with a different native session UUID;
- the same native session UUID;
- the same resolved root ID (`PI_FABRIC_MAIN_AGENT_ID`, or `session:<native UUID>`);
- the same actor-persistence session (`PI_FABRIC_SESSION_ID`, or the native UUID).

The error code is `FABRIC_DUPLICATE_LIVE_ROOT`. Fabric prints the conflict to stderr,
notifies a UI with an error, and fails activation. It does not kill either Pi or rewrite
its native session. Name changes emit `session_info_changed` and get checked again.
A conflicting rename produces a loud error and keeps Fabric's last admitted mailbox
alias; Pi's persisted name is not rolled back. Correct the name before relying on it
for message routing.

A named root's participant `name` is its admitted Pi name. Unnamed roots still publish
`main`; this generic fallback does not reserve a name. Peer labels remain unchanged.
`rootRegistrationOwnerId` is generated by Fabric and published on root records. It is
an ownership token, not a launcher-supplied identity or an environment variable.

## Refresh, reload, and takeover

Claims live in `<mesh root>/root-registrations/`. The existing mesh lock serializes
admission, rename, and release. A process-global incarnation plus the native session
UUID identifies an owner across module reloads. Refreshing that owner is allowed.
Admission adds no heartbeat and imports no optional engine at registration or idle.

A live process keeps its reservation even when its participant lease lapses. Fabric
checks PID liveness, treats unknown/permission-denied liveness as live, and checks the
Linux process start tick against PID reuse. A dead process may be taken over. An
ordinary native session retirement releases its claim after its participants close. A
same-session runtime reinitialize keeps admission continuously held. Native
`session_shutdown.reason === "reload"` preserves the file claim through module disposal;
the replacement module reclaims it as the same owner. A lightweight process-global
retained-release registry also allows a lazy replacement to release the claim at genuine
native session retirement without importing runtime engines. Main keeps its bounded
reload participant lease and journals in-flight deliveries before closing admission.
Lazy retirement removes only the exact owner-tagged reload root (including its reload
deadline) before releasing the claim; a replacement publication is never removed.
Dead claims are retained while their tagged participant leases remain visible, then retired.

Live native participant leases from older runtimes also block duplicate native-session
or root IDs. Those records have no process ownership token, so dead legacy owners may
need their leases to expire before takeover. Their generic `main` name does not reveal
the persisted Pi name. A named candidate beside such a live unclaimed generic-`main`
root is admitted with a loud stderr/UI warning: its name ownership is unknown and a
copied-name duplicate is possible. A stale or unrelated claim for the same root ID does
not suppress that warning: only a matching published owner token can correlate ownership.
Independent fresh roots stay usable. Actual
name-collision refusal across that mixed-version gap needs both roots to load the guard. An older runtime starting later cannot be forced to honor
admission by this version.

## Fresh fixture identities

Use a private mesh, profile, session directory, and a new native session UUID/file.
Give the session its unique name through `--name` or a naming extension loaded before
Fabric's `session_start` handler. Pi persists names in `session_info.name`; its session
header contains the UUID. Do not import a live session or copy its identity metadata.
Unset inherited `PI_FABRIC_PARENT_RUN`, `PI_FABRIC_ACTOR_ID`,
`PI_FABRIC_MAIN_AGENT_ID`, `PI_FABRIC_SESSION_ID`, and `PI_FABRIC_OWNER_*` for a fresh
root. Use `mesh.announce: true` when the fixture must register at startup rather than
at its first Fabric use. No new configuration flag is required.

The check is mesh-local and applies to native roots, not child agents, actors, resident
brokers, managed hosts, or mesh-disabled sessions. Mesh-disabled roots keep local
in-memory followUps but never attach to the mesh's persistent `main-followups` journal. Shared fork history (`parentSession`)
is not exclusive actor/session ownership. Names match case-sensitively after trimming.
Fresh mirrored participant leases on this mesh also refuse matching published
native/root/persistence-session IDs or explicit names; unknown generic aliases warn.
Separate hosts do not share these admission files, so absent or stale mirrors cannot
establish global uniqueness. A foreign-host claim in a shared filesystem is
conservatively treated as live. Off Linux, PID reuse
cannot be distinguished by `/proc` start ticks. Malformed or unreadable claim files
fail closed; they need owner/operator inspection, not automatic deletion.
